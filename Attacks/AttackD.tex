\section{Attack D: Shai-Hulud 2.0}
\label{sec:attackD}

Only two months after \texttt{Shai-Hulud}~1.0 (\cref{sec:attackC}),
on November 24, 2025, a new and more aggressive version was identified under the name \texttt{Shai-Hulud}~2.0~\cite{cutolo2025shaihulud20}.
This time, the \ac{SSCA} compromised 1,055 \ac{NPM} packages within a few hours~\cite{cutolo2025shaihulud20}.
The goal remained unchanged compared to the previous version, 
aiming at the theft of sensitive information such as GitHub and \ac{NPM} authentication tokens,
access keys for cloud services, and system data.
The operating mechanism was similarly preserved: as described in \cref{sec:attackC},
the attack relies on the automated execution of \texttt{TruffleHog}~\cite{trufflehog} to search for secrets in the local file system of the victim,
followed by data exfiltration through a public repository and self-propagation if valid \ac{NPM} or GitHub tokens are found.

However, this version introduces several technical differences and improvements over its predecessor~\cite{helixguard2025malicioussha1hulud}:
\begin{enumerate}
    \item \textbf{Bun Runtime:}
    Rather than operating in a Node.js environment,
    this version executes the malicious code using the Bun JavaScript runtime~\cite{sumner2026bun}, 
    enabling faster execution.

    \item \textbf{Malicious Files:}
    The tarball of each compromised package contains two new files: 
    a Bun configuration script \texttt{setup\_bun.js} and the payload \texttt{bun\_environment.js},
    which weighs over 10~MB and contains the malicious code as a single obfuscated line of 10,157,373 characters.
    The configuration script simply calls the payload file.

    \item \textbf{Obfuscated Code:}
    The malicious code employs an obfuscation technique that encodes function names, 
    variables, and constants in hexadecimal notation,
    filling \texttt{bun\_environment.js} with opaque hexadecimal tokens and effectively hiding the behavioral characteristics of the attack from static analysis.

    \item \textbf{Repository Name:}
    The repository created to exfiltrate stolen data uses a name of eighteen random characters, 
    with the fixed description ``Sha1-Hulud: The Second Coming'',
    confirming its role as the successor to the \texttt{Shai-Hulud}~1.0 attack.

    \item \textbf{Destructive Behavior:}
    Finally, if the malware fails to exfiltrate data or propagate itself,
    for example, because no valid credentials are found,
    it attempts to permanently delete the home directory of the user, destroying all local files.
\end{enumerate}

Taken together, these changes made \texttt{Shai-Hulud}~2.0 significantly more dangerous than its predecessor, 
as it spread faster, reached over a thousand packages within hours, 
and introduced destructive capabilities absent in the original version.
