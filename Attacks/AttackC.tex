\section{Attack C: Shai-Hulud 1.0}
\label{sec:attackC}

On September 15, 2025, 187 \ac{NPM} packages,
including \texttt{@ctrl/tinycolor} with over two million weekly downloads,
were compromised by the \ac{SSCA} known as \texttt{Shai-Hulud}~1.0~\cite{oxsecurity2025npm20hack}.
The initial infection vector and the identity of patient zero remain unknown;
phishing is considered the most likely hypothesis~\cite{kaspersky2025tinycolorshaikuludsupplychainattack}.
The goal of this attack is to steal sensitive information from developers and \ac{NPM} maintainers, specifically 
GitHub and \ac{NPM} authentication tokens, cloud services access keys (e.g., \ac{AWS}, Google Cloud Platform (GCP), and Azure), and local system data.

The operation of the malware can be divided into two phases:
\begin{enumerate}
    \item \textbf{Secret Scanning:} 
    When the victim finishes installing or updating a compromised package,
    a malicious script is executed that downloads, installs, and runs a platform-appropriate version of \texttt{TruffleHog}~\cite{trufflehog}.
    \texttt{TruffleHog} is a legitimate tool normally used to prevent accidental leakage of secrets in source code repositories;
    in this context, however, it is used to maliciously search for secrets in the local file system of the victim.

    \item \textbf{Validation and Propagation:} 
    After the search with \texttt{TruffleHog} completes, 
    the malware checks whether the discovered \ac{NPM} and GitHub tokens are valid and active.
    If valid \ac{NPM} credentials with publish privileges are found,
    it publishes a new malicious version for every package managed by the victim maintainer,
    embedding the same malicious code in each one;
    this self-propagation mechanism, analogous to that of a worm,
    explains the large number of packages compromised.
    If valid GitHub tokens are found, 
    the malware creates a public repository on the account of the compromised maintainer named \texttt{Shai-Hulud} 
    (like the sandworm in the \emph{Dune} novels),
    containing a \texttt{data.json} file with all the stolen information encoded.
\end{enumerate}
    
The malicious code is injected into the tarballs as a new file named \texttt{bundle.js},
which weighs approximately 3.7~MB and contains a single line of code 3,734,355 characters long.
