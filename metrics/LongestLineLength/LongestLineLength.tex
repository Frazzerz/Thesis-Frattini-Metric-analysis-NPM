\section{Analysis Metric 3: Longest Line Length}
\label{sec:analysisLLL}

\subsection{Metric Definition}
\label{sec:metricLLLDefinition}

The third metric we analyzed is the length of the longest line found in the plain text files of the \ac{NPM} packages, 
expressed in number of characters.

To compute this metric, the developed tool (\cref{sec:ToolForAnalyzingNpmPackages}) measures the length of each line 
in each plain text file by splitting the content at newline characters.
The longest line length for a single file is defined as the maximum length among all its lines.
The tool then stores the longest line length for each plain text file present in the tarball,
and subsequently, it take the maximum value among these to compute the longest line length metric for the package version.

This metric was taken into consideration because the attacks B (\cref{sec:attackB}),
C (\cref{sec:attackC}) and D (\cref{sec:attackD}) introduce malicious code written as a long single line. 
Specifically, attack B adds a single malicious line of 76,438 characters to the existing \texttt{index.js} file,
attack C adds a malicious file containing a single line of 3,734,355 characters,  
and attack D introduces a malicious file containing a single line of 10,157,373 characters.

\subsection{Goodware Dataset Scenario}
\label{sec:goodwareLLL}

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{metrics/LongestLineLength/LLL_plot1.pdf}
    \caption{Goodware dataset Trend for the Longest Line Length Metric}
    \label{fig:fig1LLL}
\end{figure}

For this metric, the Goodware dataset (\cref{sec:goodwareDataset}) contains the longest line length for each of the 20 versions of every package.

The \cref{fig:fig1LLL} and the \cref{fig:fig1LLLTrend}, show the trend of this metric across 20 versions in the Goodware dataset.
The characteristics of these figures are described in \cref{sec:Figure1}.
In both figures we can observe that the median remain stable around 460 characters across all versions.

An important characteristic of this metric is that it is influenced by the presence of build 
artifacts contained in the tarballs.
These are files automatically generated by build tools, and they can sometimes have extremely long lines.

In this analysis, we chose to consider the entire contents of the tarballs without excluding 
any file or directory a priori.
This is because an attacker could inject malicious code into any file or directory within the 
tarball, and excluding specific file types or folders a priori would have limited the analysis of this metric.

\subsection*{Analysis Outliers Packages}
\label{sec:analysisLLLOutliersPackages}

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{metrics/LongestLineLength/LLL_plot1_Trend.pdf}
    \caption{Outliers package Trend for the Longest Line Length Metric in Goodware dataset}
    \label{fig:fig1LLLTrend}
\end{figure}

In \cref{fig:fig1LLLTrend}, we highlighted several packages that exhibit outlier values 
in their versions precisely due to the presence of build artifacts within their tarballs.

\begin{itemize}

\item \textbf{next:} The \texttt{next} package, a React full-stack framework~\cite{next}, is 
represented in \cref{fig:fig1LLLTrend} by the solid green line.
In all its versions, the length of its longest line among all plain text files is 4,041,545 characters, 
making it the most extreme outlier in the Goodware dataset across all versions.

Specifically, the file containing this line is 
\texttt{app-page-turbo-experimental.runtime.\\dev.js.map}, a source map consisting of a single line only.

\texttt{Next} also contains other build artifacts, such as the file 
\texttt{app-page.runtime.dev.js}, a JavaScript file generated by build tools,
which contains 40 lines, all very long, with the longest line being 513,963 characters.

Both files are located in the \texttt{dist} folder; however, it is not guaranteed that 
build artifacts are always present in this folder, nor in any specific folder,
as their location depends entirely on the developers' choices.

\item \textbf{@angular/compiler:} In fact, in the \texttt{@angular/compiler} package 
represented in \cref{fig:fig1LLLTrend} by the solid pink line, 
in all versions the longest line is always from the \texttt{compiler.mjs.map} file contained in the \texttt{fesm2022} directory.

This package is the official compiler of the Angular framework, 
which is responsible for tasks such as translating templates with Angular syntax~\cite{angular-compiler}.
It has the second most extreme outlier value in the Goodware dataset after \texttt{next}.

It can be observed that, although the length of the longest line in this file remains constant at around 3,000,000 characters,
build artifacts may vary more or less significantly from one version to the next.
In fact, as indicated at point 1 in \cref{fig:fig1LLLTrend}, 
in version 21.0.0-rc.0 the longest line length of \texttt{compiler.mjs.map} decreased to about 2,500,000 characters.
These possible variations are attributable to the build process that generates such files.

\texttt{@angular/compiler} also contains other build artifacts, 
such as the file \texttt{compiler.mjs}, a JavaScript file generated by build tools,
containing approximately 30,000 lines, with the longest line being 14,825 characters.

\item \textbf{date-fns:} Finally, we highlighted the package date-fns in \cref{fig:fig1LLLTrend} with the solid blue line,
to show how build artifacts can be introduced in a new version without having been present in previous ones.

As indicated at point 2 in the figure, and already discussed in \cref{sec:analysisPackageSizeIncreasing},
in version 3.6.0 the developers added new files for compatibility reasons with older browsers.
Among the files added in this version is \texttt{cdn.js.map} in the \texttt{locale} directory 
containing 10 lines with the longest line being 2,188,784 characters.
This file has the longest line among all plain text files in the package.
\texttt{date-fns} also includes other build artifacts, 
such as the file \texttt{cdn.js} containing 10 lines with the longest line being 777,296 characters.

\end{itemize}
